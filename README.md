# ESP32 Xiaomi LYWSD03MMC

ESP-IDF-компонент для работы с BLE-датчиками Xiaomi LYWSD03MMC.

Компонент отвечает за распознавание MiBeacon, поиск bind-key, AES-CCM-аутентификацию и расшифровку, а также разбор измерений. BLE-сканирование, MQTT и Home Assistant находятся за пределами компонента.

## Зависимости

- ESP-IDF 5.x
- [esp32-platform-ble](https://github.com/lavrenovalexsandr-cmyk/esp32-component-ble)
- NVS и PSA Crypto из ESP-IDF

## Подключение

Репозиторий esp32-platform-ble должен быть доступен рядом с этим репозиторием либо путь к нему нужно передать через ESP32_PLATFORM_BLE_PATH.

```text
esp32/
├── esp32-platform-ble/
└── esp32_xiaomi_lywsd03/
```

Компонент main в репозитории содержит минимальный пример: инициализация NVS, Xiaomi-драйвера и BLE, приём рекламных пакетов и передача их в драйвер.

### Порядок инициализации

1. Инициализировать NVS.
2. Вызвать xiaomi_lywsd03_init().
3. Установить callback измерений через xiaomi_lywsd03_set_callback().
4. Инициализировать BLE через platform_ble_init().
5. Установить callback сканирования и запустить сканирование.

Приложение обязано инициализировать NVS до вызова xiaomi_lywsd03_init(). Функция возвращает ESP_OK при успешной инициализации и ESP_FAIL при ошибке инициализации реестра или PSA Crypto. В частности, ошибка восстановления реестра (внутренний статус STORAGE_ERROR) также приводит к ESP_FAIL на публичном уровне.

**Важно:** не вызывайте nvs_flash_erase() автоматически при ошибке nvs_flash_init() в рабочем приложении. В NVS хранится реестр датчиков и bind-key; безусловное стирание приведёт к потере ключей.

BLE callback платформы выполняется в контексте NimBLE host и не должен блокироваться. В примере рекламные пакеты копируются в очередь, а AES-CCM и обработка измерений выполняются в отдельной задаче.

## Публичный API

### Инициализация и обработка BLE

```c
esp_err_t xiaomi_lywsd03_init(void);
void xiaomi_lywsd03_set_callback(
    xiaomi_lywsd03_data_callback_t callback, void *context);
bool xiaomi_lywsd03_process_adv(const platform_ble_adv_packet_t *packet);
bool xiaomi_lywsd03_is_packet(const platform_ble_adv_packet_t *packet);
bool xiaomi_lywsd03_get_info(
    const platform_ble_adv_packet_t *packet, uint8_t mac[6]);
```

Приложение самостоятельно управляет BLE-сканированием и передаёт рекламные пакеты в xiaomi_lywsd03_process_adv(). xiaomi_lywsd03_is_packet() проверяет, относится ли пакет к LYWSD03MMC, а xiaomi_lywsd03_get_info() извлекает MAC из MiBeacon.

### Управление реестром датчиков

Bind-key должен содержать ровно 16 байт. MAC передаётся в обычном порядке байтов.

Максимальная ёмкость реестра — **16 датчиков**.

Для управления реестром рекомендуется использовать функции с подробным результатом:

```c
xiaomi_lywsd03_result_t xiaomi_lywsd03_add_sensor_ex(
    const uint8_t mac[6], const uint8_t key[16]);
xiaomi_lywsd03_result_t xiaomi_lywsd03_remove_sensor_ex(
    const uint8_t mac[6]);
xiaomi_lywsd03_result_t xiaomi_lywsd03_has_key_ex(
    const uint8_t mac[6]);
xiaomi_lywsd03_result_t xiaomi_lywsd03_sensor_count_ex(size_t *count);
xiaomi_lywsd03_result_t xiaomi_lywsd03_get_sensor_ex(
    size_t index, xiaomi_lywsd03_sensor_info_t *sensor);
```

Возможные результаты: `OK`, `NOT_FOUND`, `ALREADY_EXISTS`, `FULL`, `INVALID_ARGUMENT`, `NOT_INITIALIZED`, `BUSY`, `STORAGE_ERROR`.

- `add_sensor_ex()` возвращает `ALREADY_EXISTS`, если MAC уже зарегистрирован, и никогда не заменяет существующий ключ.
- `remove_sensor_ex()` возвращает `NOT_FOUND`, если датчик отсутствует.
- `has_key_ex()` возвращает `OK`, если ключ найден, и `NOT_FOUND`, если MAC не зарегистрирован.
- `sensor_count_ex()` записывает количество датчиков в переданный указатель.
- `get_sensor_ex()` возвращает MAC датчика по индексу; bind-key через публичный API не выдаётся.

Для замены ключа приложение должно явно выполнить удаление, затем добавление. Это защищает от случайной перезаписи ключа при повторной доставке MQTT-команды.

Старые bool/size_t-функции сохранены для совместимости. Они сворачивают подробные состояния ошибок в false или 0; для новых интеграций используйте API с суффиксом `_ex`.

Реестр защищён mutex: операции чтения, добавления, удаления и перечисления не выполняются одновременно. Ошибка чтения отдельной записи считается ошибкой хранилища, а не отсутствием датчика. В случае ошибки перечисление не должно интерпретироваться как пустой реестр.

Реестр хранится в NVS namespace `xiaomi`. Формат хранения записей сохранён. Удаление защищено журналом восстановления в NVS: после перезапуска незавершённая операция будет завершена при инициализации реестра. Если журнал повреждён или хранилище не позволяет завершить восстановление, внутренняя инициализация реестра возвращает `STORAGE_ERROR`; публичная функция `xiaomi_lywsd03_init()` в этом случае возвращает `ESP_FAIL`, и компонент не должен использоваться.

Bind-key используется внутри компонента для расшифровки и не может быть прочитан через публичный API. Временные копии ключа и plaintext очищаются после использования.

### Измерения

Структура `xiaomi_lywsd03_data_t` содержит MAC, температуру, влажность и заряд батареи. Для каждого измерения предусмотрен отдельный флаг валидности.

Callback вызывается синхронно из `xiaomi_lywsd03_process_adv()` в контексте вызывающей задачи. Не сохраняйте указатель на структуру после возврата из callback.

Поддерживаемые MiBeacon object ID:

| Object ID | Данные |
|---|---|
| 0x1004 | Температура |
| 0x1006 | Влажность |
| 0x100A | Заряд батареи |
| 0x100D | Температура и влажность |

Пакет считается успешно обработанным только после успешной AES-CCM-аутентификации и обнаружения хотя бы одного поддерживаемого измерения.

## Границы ответственности

- Компонент не запускает и не останавливает BLE-сканирование.
- Компонент не зависит от MQTT или Home Assistant.
- Приложение отвечает за получение BLE-реклам и передачу пакетов в компонент.
- Ввод bind-key и доставка ключа на ESP32 относятся к приложению и интеграции. Компонент предоставляет API регистрации и хранения.
